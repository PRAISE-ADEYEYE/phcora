# PHCORA

Primary Healthcare Risk and Early Warning Intelligence

Live demo: https://phcora.vercel.app

PHCORA is a triage tool for a state supply officer. It answers one question: which primary health centres should we call or supply first this cycle, and how sure are we?

Built for the YDP Datathon 2026, Health track.

## The problem

Facility level HMIS reporting is late, partial or missing, so a stockout often stays invisible until a patient arrives. A supply officer cannot tell which clinics are running low and which are only silent.

## What PHCORA does

Each clinic gets two separate answers:

* Risk: the chance that stock runs out before a resupply can arrive, estimated only from what the clinic reported.
* Trust: how far its reports can be relied on, from missed and late reports.

Silence widens the uncertainty. A missing report is never treated as a stockout.

These two answers become one of four actions:

* Resupply: high risk, reliable reports.
* Verify then resupply: high risk, weak reports.
* Verify: looks fine, but reports are too weak to trust (hidden risk).
* Watch: low risk, reliable reports.

## What is in the app

* Landing page explaining the problem and the approach.
* Sign in and sign up with Firebase (Google and email).
* Dashboard with Overview, Map and Ask PHCORA.
* Ask PHCORA is an AI assistant served by a Cloudflare Worker, using Groq with Gemini as fallback. Conversations are saved to Firestore.
* Installable as a PWA.

## Data: what is real and what is simulated

| Layer | Source | Status |
|---|---|---|
| Clinic names and locations | GRID3 NGA Health Facilities v2.0 (CC BY) | Real |
| LGA boundaries | OCHA Nigeria Administrative Boundaries (CC BY) | Real |
| State survey shares of PHCs with medications and restock tables | CheckMyPHC (CC BY), see data/calibration.json | Real |
| National benchmark of PHCs with essential medicines | National Health Facility Survey 2023 | Real, quoted as context only |
| Monthly stock, use, receipts and report arrival | Generated by pipeline/build_data.py | Simulated, always flagged simulated=true |
| Resupply lead time, effect of a missed report on risk | assumptions.json | Assumed |

No public facility level stock history exists for Nigeria, so no real stockout labels are available. The simulator is tuned so the share of clinics with medications in each state matches the CheckMyPHC survey. Nothing in the app should be read as the real stock level of a real clinic.

## Method

The risk engine is a transparent statistical stock balance model, not a trained machine learning model. It infers monthly net depletion from consecutive reported months, projects stock to the end of the resupply lead time with an uncertainty range that grows with silence, and adds extra risk for missed reports using an assumed parameter. Reasons for each flag are generated from the same numbers.

Why no trained model: with simulated labels, a trained model would only learn the simulator.

## Evaluation inside the simulator

pipeline/build_data.py compares the triage against simple rules and random visits across many simulated worlds and writes data/evaluation.json. These results describe how the method behaves under stated assumptions. They are not accuracy on real clinics.

See data/evaluation.json for the exact figures from the final run.

## Rebuild the data

The data is built by GitHub Actions, so nothing needs to run on a local computer.

1. Open the Actions tab, choose Build PHCORA data, and click Run workflow.
2. Paste the direct download links for the GRID3 Health Facilities v2.0 file (CSV or GeoJSON) and the OCHA LGA boundaries (GeoJSON).
3. The workflow downloads, cleans, simulates, scores, validates and commits facilities.geojson, lga.geojson, assumptions.json, cleaning_log.json and evaluation.json into data/.

To run it locally instead (Python 3.9 or newer):

python3 pipeline/build_data.py --facilities raw/FACILITIES_FILE --lga raw/LGA_FILE.geojson
python3 pipeline/validate_data.py data

## Deploy

* Frontend: Vercel, import this repository, framework preset Other, no build command.
* API: paste worker.js into a Cloudflare Worker and set these variables: GROQ_API_KEY, GEMINI_API_KEY, FIREBASE_SERVICE_ACCOUNT, FIREBASE_PROJECT_ID, ALLOWED_ORIGIN, SITE_URL. Secrets are never stored in this repository.

## Limitations

* Stock and reporting histories are simulated.
* The effect of a missed report on risk is an assumption, not a measured value.
* One tracer commodity (ACT, an antimalarial) is modelled.
* GRID3 facility data is described by its publisher as non exhaustive and not validated.
* Monthly reporting cadence means PHCORA works at monthly resolution, not daily forecasts.
* Pilot path: monthly stock and reporting data from a state HMIS or eLMIS under a data sharing agreement would replace the simulated histories.

## How AI tools were used

Claude (Anthropic) was used for research on data sources, for design discussion of the approach, and for drafting and debugging code. The decisions on scope, problem framing, data labelling and what to leave out were made by the author. All simulated data is labelled and all assumptions are listed in assumptions.json.
